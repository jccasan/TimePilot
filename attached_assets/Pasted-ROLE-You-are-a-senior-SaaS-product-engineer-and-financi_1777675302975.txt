ROLE
You are a senior SaaS product engineer and financial modeling engineer. You are working on Scoopilot’s job profitability / route economics module for pet waste removal businesses.

GOAL
Fix the job economics and current route impact calculations so the app no longer mixes pricing economics, actual route profitability, and route-density impact into one misleading number.

The current screen is producing bad outputs because:
- Revenue is showing $0.00 even when the job should have a price.
- Profitability is calculated from missing or zero revenue.
- Labor appears to be calculated only on service time.
- Travel cost appears to include vehicle cost but not travel labor.
- Overhead per visit is very high and needs to be clearly labeled as allocated overhead.
- Recommended price, projected margin, and displayed total cost are inconsistent.
- “Job Economics” and “Current Route Impact” are being blended instead of separated.

Build this carefully. Do not just patch labels. Fix the underlying calculation model.

==================================================
SECTION 1: CORE PRINCIPLE
==================================================

The app must show three separate financial views:

1. JOB PRICE HEALTH
Purpose:
Determines whether the job is priced correctly using target route assumptions.

Use this for:
- Recommended price
- Pricing warnings
- Target margin
- “Should I raise this customer’s price?”

Do NOT use actual current route placement for this metric.

2. CURRENT ROUTE PROFITABILITY
Purpose:
Determines whether the job is profitable where it currently sits in today’s route.

Use this for:
- Route profitability
- Current route impact
- Route cleanup
- Identifying jobs that are too far away or inefficiently sequenced

This view must include actual travel labor and actual vehicle travel cost.

3. ROUTE DENSITY OPPORTUNITY
Purpose:
Determines whether the job is actually bad or just poorly routed.

Use this for:
- Showing excess travel time
- Showing excess travel cost
- Telling the owner whether the job should be repriced, moved to a better day, or clustered with nearby work

==================================================
SECTION 2: REQUIRED INPUTS
==================================================

Each job needs the following inputs available to the calculation engine:

CUSTOMER / JOB INPUTS
- currentPricePerVisit
- serviceMinutes
- visitFrequency
- estimatedSuppliesPerVisit
- customerAddress
- assignedRouteId
- assignedDay

LABOR INPUTS
- hourlyWage
- laborBurdenMultiplier
- fullyLoadedLaborRate

Formula:
fullyLoadedLaborRate = hourlyWage * laborBurdenMultiplier

Example:
hourlyWage = 15.00
laborBurdenMultiplier = 1.40
fullyLoadedLaborRate = 21.00/hr

TRAVEL INPUTS
- targetTravelMinutes
- actualTravelMinutes
- actualTravelMiles
- vehicleCostPerMile
- estimatedDistanceFlag if distance is estimated

OVERHEAD INPUTS
- monthlyOverhead
- estimatedMonthlyVisits
- allocatedOverheadPerVisit

Formula:
allocatedOverheadPerVisit = monthlyOverhead / estimatedMonthlyVisits

TARGET PRICING INPUTS
- targetMarginPercent
Default: 31%
- roundingIncrement
Default: $1.00

==================================================
SECTION 3: FORMULAS
==================================================

A. SERVICE LABOR COST

serviceLaborCost = (serviceMinutes / 60) * fullyLoadedLaborRate

Example:
10 minutes at $21/hr:
10 / 60 * 21 = $3.50

B. TARGET TRAVEL COST

Target travel is used for pricing health only.

targetTravelLaborCost = (targetTravelMinutes / 60) * fullyLoadedLaborRate

targetTravelVehicleCost = targetTravelMiles * vehicleCostPerMile

If targetTravelMiles is unavailable, estimate it from actual miles proportionally if safe:
targetTravelMiles = actualTravelMiles * (targetTravelMinutes / actualTravelMinutes)

If actualTravelMinutes is 0 or missing, use 0 for targetTravelVehicleCost and show a warning:
“Target travel mileage unavailable.”

targetTravelCost = targetTravelLaborCost + targetTravelVehicleCost

C. ACTUAL ROUTE TRAVEL COST

Actual travel is used for current route profitability only.

actualTravelLaborCost = (actualTravelMinutes / 60) * fullyLoadedLaborRate

actualTravelVehicleCost = actualTravelMiles * vehicleCostPerMile

actualTravelCost = actualTravelLaborCost + actualTravelVehicleCost

D. ALLOCATED OVERHEAD

allocatedOverheadPerVisit = monthlyOverhead / estimatedMonthlyVisits

Validation:
If estimatedMonthlyVisits is missing, null, or 0:
- Do not divide by zero.
- Set allocatedOverheadPerVisit to 0.
- Show warning:
“Overhead allocation unavailable because estimated monthly visits is missing.”

E. JOB PRICE HEALTH COST

targetCostPerVisit =
  serviceLaborCost
  + targetTravelCost
  + estimatedSuppliesPerVisit
  + allocatedOverheadPerVisit

recommendedPrice =
  targetCostPerVisit / (1 - targetMarginPercent)

Round recommendedPrice up to the nearest roundingIncrement.

Example:
targetCostPerVisit = 28.39
targetMarginPercent = 0.31
recommendedPrice = 28.39 / 0.69 = 41.14
rounded recommendedPrice = 42.00 if rounding up to nearest $1
OR 41.00 only if using normal rounding.

Important:
Use consistent rounding rules.
Preferred rule:
Round UP to nearest $1 so the target margin is not accidentally undercut.

projectedMargin =
  (recommendedPrice - targetCostPerVisit) / recommendedPrice

F. CURRENT ROUTE PROFITABILITY

actualCostPerVisit =
  serviceLaborCost
  + actualTravelCost
  + estimatedSuppliesPerVisit
  + allocatedOverheadPerVisit

actualProfitPerVisit =
  currentPricePerVisit - actualCostPerVisit

actualMargin =
  actualProfitPerVisit / currentPricePerVisit

If currentPricePerVisit is missing or 0:
- Do not show margin as 0.0%.
- Show “N/A”
- Show warning:
“Current price is missing, so actual profit and margin cannot be calculated.”

G. EFFECTIVE HOURLY RATE

Do not calculate effective hourly rate using profit only unless clearly labeled.

actualJobMinutes =
  serviceMinutes + actualTravelMinutes

targetJobMinutes =
  serviceMinutes + targetTravelMinutes

actualRevenuePerHour =
  currentPricePerVisit / (actualJobMinutes / 60)

actualProfitPerHour =
  actualProfitPerVisit / (actualJobMinutes / 60)

targetRevenuePerHour =
  recommendedPrice / (targetJobMinutes / 60)

targetProfitPerHour =
  (recommendedPrice - targetCostPerVisit) / (targetJobMinutes / 60)

If currentPricePerVisit is missing or 0:
- actualRevenuePerHour = N/A
- actualProfitPerHour = N/A

H. ROUTE DENSITY OPPORTUNITY

excessTravelMinutes =
  max(actualTravelMinutes - targetTravelMinutes, 0)

excessTravelLaborCost =
  (excessTravelMinutes / 60) * fullyLoadedLaborRate

excessTravelVehicleCost =
  max(actualTravelMiles - targetTravelMiles, 0) * vehicleCostPerMile

excessTravelCost =
  excessTravelLaborCost + excessTravelVehicleCost

densityOpportunityText logic:

If currentPricePerVisit is missing or 0:
“Set a current price before judging route profitability.”

Else if actualMargin < targetMarginPercent and excessTravelMinutes > 5:
“This job may not be underpriced. It may be badly routed. Try moving it to a denser route/day before raising price.”

Else if actualMargin < targetMarginPercent and excessTravelMinutes <= 5:
“This job appears underpriced even with reasonable route density.”

Else:
“This job is profitable in its current route position.”

SECTION 10: IMPORTANT PRODUCT INTENT
==================================================

Do not make the app tell users to raise prices simply because a job is badly routed.

A job can be:
- correctly priced but badly routed
- underpriced even on a good route
- profitable only when clustered
- unprofitable because overhead allocation is too high at low business volume

The app must help the owner understand which one is true.

Build the calculation engine and UI around that distinction.
