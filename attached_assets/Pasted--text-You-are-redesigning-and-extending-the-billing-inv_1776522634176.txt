```text
You are redesigning and extending the billing, invoicing, collections, and billing automation system for Scoopilot, a route-based field-service SaaS for recurring home service businesses such as pet waste removal, dog walking, and similar service businesses.

Your job is to rebuild this area of the product into a true revenue engine.

This is not a generic invoicing project.
This is a cash flow, collections, and billing automation project.

==================================================
PROJECT GOAL
==================================================

Transform Scoopilot’s current invoicing and billing system from a passive invoice list with fragmented billing rules into a structured, action-first revenue system that:

- minimizes manual invoicing
- prevents billing errors and double billing
- supports system-wide billing defaults
- supports service-level billing rules
- supports customer-level overrides
- gives users clear visibility into uninvoiced work, upcoming charges, unpaid invoices, overdue invoices, and collected revenue
- makes money-related actions obvious and easy
- improves autopay adoption and autopay execution
- makes billing feel automatic, supervised, and trustworthy

Core principle:
Invoices are not documents.
They are cash flow events.

Secondary principle:
Users should experience this screen as:
1. See money
2. Click one action
3. Money moves

==================================================
IMPLEMENTATION RULES
==================================================

- Use React
- Build production-quality code
- Use reusable components
- Use maintainable state management
- Use clean conditional rendering
- Optimize for desktop first, but support tablet and mobile
- Avoid enterprise clutter and unnecessary visual noise
- Prefer batch workflows over one-off workflows
- Make money totals, counts, and actions visible everywhere they matter
- Remove confusing duplication and weak wording
- Prevent double billing at the system level, not just visually
- Preserve existing invoicing functionality where useful, but restructure the UX around collections and automation

==================================================
NON-NEGOTIABLE BUSINESS RULES
==================================================

1. Duplicate invoice generation actions must be eliminated.
If the UI currently contains both:
- Generate invoices
- Generate from completed work

They must be consolidated into a single primary action:
- Generate All Invoices

With optional dropdown actions:
- Generate by Customer
- Generate by Date Range
- Generate Selected

2. Uninvoiced work must support a clear bulk action.
If the system shows uninvoiced visits and a total dollar amount, there must be a dominant CTA:
- Generate All ($X)

3. Double billing must be prevented.
Once work is invoiced:
- related visits must be marked as invoiced
- they must be removed from Uninvoiced view
- they must not be invoiceable again unless explicitly reversed by a deliberate reversal or credit workflow

4. Invoice statuses must be simplified and made business-readable.
Use only:
- Uninvoiced
- Unpaid
- Overdue
- Paid
- Failed

Remove or merge vague labels like:
- Pending
- Awaiting Payment
- Sent

5. Actions must attach directly to money.
Examples:
- Outstanding -> Send All Unpaid
- Overdue -> Send Reminders
- Autopay -> Charge $X across Y customers

6. Billing logic must be structured into three layers:
- System Defaults
- Service-Level Billing Rules
- Customer Overrides
```
