## Fix 1 — Configurable Pipeline Stages

### Problem
Pipeline stages are hardcoded as `["lead", "qualified", "proposal", "negotiation", "closed_won", "closed_lost"]` in `server/routes/crm.ts` line 224. Operators cannot customize them.

### Schema Change
Add a new table to `shared/crm-schema.ts`:

```
crmPipelineStages
  id: varchar PK, gen_random_uuid()
  companyId: varchar FK → companies.id, onDelete: cascade, notNull
  name: text, notNull — display name e.g. "Follow-up Scheduled"
  slug: text, notNull — machine key e.g. "follow_up_scheduled", used in crmDeals.stage
  color: text, nullable — hex color for kanban display
  position: integer, notNull — sort order, 0-indexed
  isWon: boolean, notNull, default: false — marks this as a "won" terminal stage
  isLost: boolean, notNull, default: false — marks this as a "lost" terminal stage
  createdAt: timestamp, defaultNow(), notNull

  Unique constraint: (companyId, slug)
  Index: (companyId, position)
```

Run `npx drizzle-kit generate`, show output, stop for confirmation.

### Default Stages
When a company accesses `/api/crm/pipeline-stages` for the first time and has no stages, seed the defaults:

```
{ name: "Lead",        slug: "lead",        position: 0, isWon: false, isLost: false }
{ name: "Qualified",   slug: "qualified",   position: 1, isWon: false, isLost: false }
{ name: "Proposal",    slug: "proposal",    position: 2, isWon: false, isLost: false }
{ name: "Negotiation", slug: "negotiation", position: 3, isWon: false, isLost: false }
{ name: "Closed Won",  slug: "closed_won",  position: 4, isWon: true,  isLost: false }
{ name: "Closed Lost", slug: "closed_lost", position: 5, isWon: false, isLost: true  }
```

### API Endpoints (add to crm.ts)
```
GET    /api/crm/pipeline-stages           — list stages for company, sorted by position. Seed defaults if empty.
POST   /api/crm/pipeline-stages           — create stage. Body: { name, color?, position? }. Auto-generates slug from name.
PATCH  /api/crm/pipeline-stages/:id       — update name, color, position, isWon, isLost
DELETE /api/crm/pipeline-stages/:id       — only if no deals use this stage. Return 400 with count if deals exist.
POST   /api/crm/pipeline-stages/reorder   — body: { stages: [{ id, position }] }. Bulk update positions.
```

## Fix 5 — Two-Way Contact Sync

### Problem
`POST /api/crm/contacts/sync-from-customers` pushes operational contacts (scooping clients) into CRM. The reverse — when a CRM lead converts to a paying client — does nothing automatically.

### What "converts" means
A CRM contact converts when a deal linked to that contact reaches a stage where `isWon = true` (from Fix 1). This is the trigger.

### Implementation
In the `PATCH /api/crm/deals/:id` handler, after updating the deal:

```typescript
// If deal stage changed to a won stage (isWon = true):
if (updatedDeal.stage changed AND newStage.isWon === true) {
  // Find the linked CRM contact
  const crmContact = await db.select().from(crmContacts)
    .where(and(eq(crmContacts.id, deal.contactId), eq(crmContacts.companyId, companyId)))
    .limit(1);

  if (crmContact && crmContact.mainContactId) {
    // Already linked to an operational contact — nothing to do
  } else if (crmContact) {
    // Check if an operational contact exists with matching email
    const existing = await db.select().from(operationalContacts)
      .where(and(
        eq(operationalContacts.companyId, companyId),
        eq(operationalContacts.email, crmContact.email)
      )).limit(1);

    if (existing.length === 0 && crmContact.email) {
      // Create operational contact from CRM contact data
      const newContact = await storage.createContact({
        companyId,
        firstName: crmContact.firstName,
        lastName: crmContact.lastName,
        email: crmContact.email,
        phone: crmContact.phone ?? undefined,
        status: 'estimate', // not yet active, just created
      });
      // Link back
      await db.update(crmContacts)
        .set({ mainContactId: newContact.id.toString() })
        .where(eq(crmContacts.id, crmContact.id));
    } else if (existing.length > 0) {
      // Link to existing operational contact
      await db.update(crmContacts)
        .set({ mainContactId: existing[0].id.toString() })
        .where(eq(crmContacts.id, crmContact.id));
    }
  }
}
```

No UI change required. The link is visible on the CRM contact record via the existing `mainContactId` field — add a "Linked Client" badge on the contact detail page showing the operational contact name with a link to their client record.
