You are updating the profitability engine and UI logic for a route-based service business SaaS. The current system incorrectly mixes job economics with current route conditions. The goal is to separate those concepts cleanly so pricing decisions are not distorted by bad routing, while still showing actual operational performance.

Build this in a task/subtask format and follow the intent exactly.

PROJECT GOAL

We need to split profitability into multiple layers:

1. Job profitability
2. Route profitability
3. Overall system profitability

The key principle is this:

A job can be a good job but currently sitting in a bad route.

Example:
- A property may produce strong profit under ideal route density
- But look weak if it currently has 20 minutes of drive time around it
- That does NOT mean the job itself is bad
- It means the route assignment or density is bad

So the software must stop judging job quality solely based on current route travel time.

CORE BUSINESS LOGIC

We need at least 2 primary metrics for each job:

A. JOB METRIC
This is the standardized unit economics of the job itself.
It should ignore the current route assignment and instead use ideal or target assumptions.

Purpose:
- Pricing decisions
- Recommended price logic
- Determining whether a customer/job is worth selling at all
- Understanding per-unit economics

B. CURRENT ROUTE METRIC
This is the actual profitability of the job as currently scheduled and routed.

Purpose:
- Operations decisions
- Route health
- Whether the route is inefficient
- Whether this stop is currently dragging down hourly profit

Then we also need:

C. OVERALL PROFITABILITY
Rollup views across routes and the business overall.

Purpose:
- Business health
- Average actual profit/hour
- Route comparison
- Staffing and expansion decisions

IMPORTANT INTENT

Do NOT let current bad routing make a good job appear fundamentally bad.

We need to separate:
- “Is this a good job to have?”
from
- “Is this job in a good route right now?”

Those are different questions and must be calculated separately.

TASK 2: DEFINE THE BUSINESS RULES CLEARLY
==================================================

Implement these business rules exactly.

--------------------------------------------------
SUBTASK 2.1: SEPARATE JOB QUALITY FROM ROUTE QUALITY
--------------------------------------------------

The system must distinguish between:
- Job quality
- Route quality

Definitions:

Job quality:
How profitable the stop is under standardized, target-density assumptions.

Route quality:
How profitable the stop is in its current real-world route placement.

Rule:
A job must not be marked as weak simply because it is in a bad route.

Example:
- Ideal profit/hour = strong
- Actual route profit/hour = weak

Interpretation:
- Good job
- Bad route placement

The UI and logic should preserve that distinction.

--------------------------------------------------
SUBTASK 2.2: PRICING MUST USE JOB-LEVEL ECONOMICS
--------------------------------------------------

Recommended price and minimum price logic should be based primarily on job-level profitability, not current route assignment.

Reason:
Current routes change.
If pricing is based on a temporary bad route, the system will overreact and misprice jobs.

Exception:
If a property is structurally isolated and will almost always require high travel regardless of route density, allow an optional “isolation/travel penalty” adjustment.

This should be a separate property-level or territory-level factor, not mixed into every route calculation by default.

--------------------------------------------------
SUBTASK 2.3: ROUTE OPTIMIZATION MUST USE ACTUAL PROFITABILITY
--------------------------------------------------

Operations views and route management should use actual profitability and actual route time.

Reason:
We need to know how the business is performing today, not under ideal assumptions.

Use route-level metrics for:
- Route comparison
- Route optimization decisions
- Identifying poorly clustered stops
- Reassignment opportunities
- Capacity planning

TASK 9: SUGGESTED FORMULAS / CALCULATION INTENT
==================================================

Use this intent unless existing architecture requires small adaptation.

JOB-LEVEL

standard_total_minutes =
service_minutes + standard_travel_minutes

standard_labor_cost =
(standard_total_minutes / 60) * burdened_hourly_rate

job_total_cost =
standard_labor_cost + supplies_cost + overhead_per_visit + any_standardized_travel_cost_if_used

job_profit_per_visit =
revenue_per_visit - job_total_cost

job_profit_per_hour =
job_profit_per_visit / (standard_total_minutes / 60)

ROUTE-LEVEL

actual_total_minutes =
actual_drive_minutes + actual_service_minutes

actual_labor_cost =
(actual_total_minutes / 60) * burdened_hourly_rate

actual_travel_cost =
actual_miles * vehicle_cost_per_mile

actual_total_cost =
actual_labor_cost + actual_travel_cost + supplies_cost + overhead_per_visit

actual_profit_per_visit =
revenue_per_visit - actual_total_cost

actual_profit_per_hour =
actual_profit_per_visit / (actual_total_minutes / 60)

SYSTEM-LEVEL

aggregate using sums and weighted averages where appropriate, especially for profit/hour and minutes.
