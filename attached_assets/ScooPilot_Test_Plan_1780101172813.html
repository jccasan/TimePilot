01 500 Error Surface Testing P0 — Blocker Risk
Context
Errors are intermittent and solo-triggered. Goal is to hit boundary conditions that historically correlate with 500s: empty states, large data sets, rapid sequential actions, and navigation edge cases.
1.1
Empty State Boundary Conditions
Trigger actions with zero underlying data to expose unhandled nulls
Blocker
Steps
  1. Create a brand new account with no clients, no routes, no visits.
  2. Attempt to run route optimization with zero stops assigned.
  3. Attempt to generate batch invoices with no completed visits.
  4. Attempt to load the analytics dashboard before any visits exist.
  5. Attempt to run AI Business Assessment on a zero-data account.
  6. Open Rover and ask it to "show today's route progress" on an empty account.
  7. Attempt to export contacts with zero contacts in the database.
Pass CriteriaEmpty states return graceful UI messages, not 500 errors or blank white screens.
Watch ForAny action that spins indefinitely, returns a raw error, or crashes the page. Log the exact action and URL.
1.2
Rapid Sequential Action Testing
Simulate impatient users double-clicking or rapidly submitting forms
Blocker
Steps
  1. Double-click "Save" on a new client record rapidly.
  2. Double-click "Generate Invoices" in batch invoicing.
  3. Click "Optimize Route" twice in fast succession.
  4. Rapidly save and re-open a quote being edited.
  5. Quickly navigate away from a form mid-save and return.
Pass CriteriaNo duplicate records created. No 500 errors. Buttons disable after first click or show a loading state.
Watch ForDuplicate invoice generation, duplicate client records, or a hung loading state with no recovery.
1.3
Large Data Set Page Loads
Simulate accounts with significant data volume
High
Steps
  1. Import 100+ client records via CSV into a test account.
  2. Generate 6 months of recurring visits for all clients (bulk generation).
  3. Load the full schedule view in month mode.
  4. Load the analytics dashboard and all chart widgets.
  5. Load the route builder with all stops visible.
  6. Run a global search for a common term (e.g., "John") and observe response time.
Pass CriteriaAll pages load under 5 seconds. No 500s. Charts render correctly.
Watch ForTimeout errors on visit generation, chart rendering failures, or map rendering breakdown with many pins.
02 Onboarding Flow P1 — High
Context
First impression for every new signup. A broken or confusing onboarding loses the account before they ever see the product. Test both the happy path and the "I'll skip this" path.
2.1
Full Onboarding Happy Path
Confirm wizard completes cleanly end-to-end
Blocker
Steps
  1. Create a fresh test account and begin onboarding wizard.
  2. Complete Step 1: Company profile with full valid data.
  3. Step 2: Enter a real business website URL and confirm AI extraction populates fields correctly.
  4. Step 3: Configure pricing with at least 2 service tiers.
  5. Step 4: Complete Stripe Connect with a test account.
  6. Step 5: Launch and confirm dashboard loads with correct company data.
  7. Verify company logo, name, and branding appear on a test quote/invoice.
Pass CriteriaAll 5 steps complete without errors. Dashboard loads. Branding is applied correctly throughout.
2.2
Onboarding Skip / Partial Completion
Confirm system doesn't break if user skips steps or exits mid-flow
High
Steps
  1. Start onboarding, complete Step 1, then close the browser and return.
  2. Confirm wizard resumes at the correct step (not restarted).
  3. Skip the AI website extraction step entirely and proceed.
  4. Skip Stripe Connect and attempt to launch.
  5. Confirm the dashboard loads and is functional without Stripe connected.
  6. Confirm payment-dependent features show appropriate prompts (not 500 errors).
Pass CriteriaPartial completion doesn't break the account. User can always reach the dashboard. Missing setup shows prompts, not crashes.
2.3
AI Website Extraction Edge Cases
Test extraction with bad/edge-case URLs
Medium
Steps
  1. Enter a URL that returns a 404.
  2. Enter a URL for a site with no relevant business content (e.g., google.com).
  3. Enter a URL for a site that blocks scrapers.
  4. Enter a malformed URL (no https, typo domain).
  5. Leave the URL field blank and attempt to proceed.
Pass CriteriaAll cases return graceful error messages. Wizard remains functional. No 500 errors.

04 Route Optimization & Multi-Depot Stress Test P0 — Critical
Multi-Depot Simulation Setup
Since you don't have the real account's data, use this synthetic scenario: 8 depots across a metro area, 2 techs per depot (16 total), 15–20 stops per tech per day. This approximates a realistic load for that account type.
4.1
Single Route Optimization (Baseline)
Confirm optimization works correctly before adding scale
Blocker
Steps
  1. Build a route with 20 stops across a realistic geographic area.
  2. Run one-click optimization. Record time to complete.
  3. Confirm stop order changes reflect actual shortest path (spot-check 3 stops on map).
  4. Lock the route. Attempt to run optimization again. Confirm lock is respected.
  5. Manually reorder 3 stops. Confirm drag-and-drop saves correctly.
  6. Run optimization on a route with only 1 stop. Confirm graceful handling.
Pass CriteriaOptimization completes under 10 seconds for 20 stops. Route lock prevents re-optimization. Single-stop route doesn't error.
4.2
Multi-Depot Stress Test — 8 Locations
Simulate the large incoming account before they go live
Blocker
Steps
  1. Create a test company with 8 depot locations spread across a metro area.
  2. Add 16 technician user accounts (2 per depot).
  3. Import or manually create ~200 client stops distributed across all 8 depot zones.
  4. Assign stops to techs by depot zone (roughly 12–15 stops per tech).
  5. Run route optimization for all routes simultaneously (or sequentially — note which).
  6. Confirm each depot's routes optimize independently without cross-contamination.
  7. Switch to map view. Confirm all 200 stops render without performance breakdown.
  8. Have two "techs" work routes simultaneously in separate browser sessions.
  9. Confirm real-time progress updates reflect across both sessions.
  10. Generate bulk invoices for all 200 clients after marking visits complete.
Pass CriteriaAll 8 depots optimize cleanly. No cross-depot stop contamination. Map renders without crashing. Concurrent sessions don't interfere. Bulk invoice generation completes.
Watch ForOptimization timing out on larger route sets. Mapbox rate limits with 200 stops. WebSocket conflicts between concurrent tech sessions. Invoice batch hanging or partial generation.
4.3
Route Performance Under Concurrent Users
Multiple techs updating visit status simultaneously
High
Steps
  1. Open 5 separate browser sessions (incognito windows), each logged in as a different tech.
  2. Have all 5 simultaneously mark a visit complete at the same time.
  3. Confirm all completions are recorded and none are lost.
  4. Have one admin session open on the dashboard watching progress in real-time.
  5. Confirm admin dashboard updates reflect all 5 completions within a few seconds.
Pass CriteriaNo lost completions. Admin view updates without manual refresh. No 500 errors under concurrent load.
